This document formalizes the expected quality and verification gates for the `@community-rss/core` framework.

## 1. Coverage Thresholds

The framework maintains strict enforcement on test verification metrics:
- All core `utils/` functions MUST feature dedicated unit tests. 
- The suite must structurally assure ≥80% test-coverage minimums on statements, branches, functions, and lines. 
- Submissions showing negative performance in code coverage relative to the `main` branch will be explicitly rejected by CI.

## 2. Unit and Component Tests (Vitest)

- Unit and component behavioral tests run exclusively on Node configurations driven by Vitest. 
- Database functionality unit models use in-memory instances of `better-sqlite3` isolated from external system pollution instead of distributed test harnesses like D1 or Miniflare models.

## 3. End-to-End Testing (Playwright)

- Live user interface, interaction loops, full authentication (magic-links), component reactivity, and DOM behaviors are verified by Playwright within the `e2e/` testing blocks.
- Playwright configurations test against the actively running playground ecosystem. The environment should gracefully exit/skip these tests if it detects an absence of standard Docker development instances (like Mailpit, or MinIO).

## 4. Requirement Verification

The reference requirements must be directly tested. The reference Community RSS application generated by the package constitutes what is primarily verified by the functional automated suites to prevent regressions of the core baseline platform against this specification.
